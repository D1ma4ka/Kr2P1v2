# P8.4 — будущие интеграции (проект, не действующий API)

Существующие AccountApi, каталог, checkins, wishlist, badges и ACL сохраняются.
Новых endpoint в P8.4 нет. Коллекции, поисковая история и локальные напоминания
не означают успешную синхронизацию; аналитика ограничена доступным кэшем.

Будущий репозиторий синхронизации должен принимать операции с UUID operationId,
entityId, ownerUserId, createdAt/updatedAt (UTC), localVersion, baseRemoteVersion,
tombstone и dirty state. Сервер проверяет владельца по сессии, а не доверяет
ownerUserId клиента. Повтор operationId идемпотентен. ACK только после durable
server commit. До ACK клиент сохраняет локальную запись и tombstones.

Коллекции и membership — разные сущности; ключ membership collectionId+positionId
предотвращает дубли. Варианты упаковки сохраняют существующий positionId.
Переименование при конфликте требует сравнения base version; удаление доминирует
над устаревшим add, независимые membership объединяются. Не использовать часы
устройства как единственное основание для разрешения конфликта. История поиска
и reminders остаются локальными по умолчанию, загрузка требует отдельного решения.

Будущие server recommendations и notification sources — отдельные интерфейсы;
не подменяют local selection и не присваивают server badges. Перед расширением
нужны OpenAPI, серверная авторизация, тесты конфликтов/повторов/удалений и политика
отзыва карточек. Неполная история/TTL не доказывает полный вкус или полный год.


## Реализованные клиентские границы P8.4

- `AccountStore` SQLite v4: additive `local_documents`, тот же AES-GCM/Keystore;
  `AccountApi.localDocument/editLocalDocument` проверяют сессию и сериализуют запись.
- `CollectionsRepository : CollectionSyncSource`: JSON schemaVersion1,
  collection/membership UUID+owner+createdAt/updatedAt+localVersion+dirty+deleted.
  Порядок members передаётся порядком массива; будущий adapter должен определить
  server sort key. `pendingCollections()` возвращает dirty/tombstones, ничего не
  отправляет и не очищает dirty без будущего подтверждённого ACK.
- `CatalogHistory`: локальные queries/recent IDs/applied filters, не синхронизируются.
- `CachedPersonalSource : AvailableCardsSource`: только TTL24h account cache,
  latest version per checkin UUID; badges — только подтверждённые snapshots.
  `LocalDiscovery` и `FutureRecommendationSource` разделены, server source не создан.
- `ReminderRepository`: schemaVersion1, UUID/owner/time/version, read/deleted/cancelled,
  локальные events; `FutureNotificationSource` зарезервирован для настоящих событий.
  JobScheduler срабатывает только для текущего владельца сохранённой сессии;
  logout не обещает доставку, Doze может её отложить. Нет рекламных/социальных push.
- `ShareImages`: cache-only PNG и Android content URI, нет upload или public URL.

После logout/login данные локальных документов сохраняются по прежней политике
preserveDrafts; явная подтверждённая очистка удаляет документы всех аккаунтов на
этом устройстве. Необходимы будущие export/restore/серверный sync для восстановления
подборок на другом устройстве. Ни APK cache, ни SQLite не заявляются cloud backup.
