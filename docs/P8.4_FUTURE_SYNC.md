# P8.4 — будущие интеграции (проект, не действующий API)

Существующие AccountApi, каталог, checkins, wishlist, badges и ACL сохраняются.
Новых endpoint в P8.4 нет. Коллекции, поисковая история и локальные напоминания
не означают успешную синхронизацию; аналитика ограничена доступным кэшем.

Будущий репозиторий синхронизации должен принимать операции с UUID operationId,
entityId, ownerUserId, createdAt/updatedAt (UTC), localVersion, baseRemoteVersion,
tombstone и dirty state. Сервер проверяет владельца по сессии, а не доверяет
ownerUserId клиента. Повтор operationId идемпотентен. ACK только после durable
server commit. До ACK клиент сохраняет локальную запись и tombstones.

Коллекции и membership — разные сущности; ключ membership collectionId+positionId
предотвращает дубли. Варианты упаковки сохраняют существующий positionId.
Переименование при конфликте требует сравнения base version; удаление доминирует
над устаревшим add, независимые membership объединяются. Не использовать часы
устройства как единственное основание для разрешения конфликта. История поиска
и reminders остаются локальными по умолчанию, загрузка требует отдельного решения.

Будущие server recommendations и notification sources — отдельные интерфейсы;
не подменяют local selection и не присваивают server badges. Перед расширением
нужны OpenAPI, серверная авторизация, тесты конфликтов/повторов/удалений и политика
отзыва карточек. Неполная история/TTL не доказывает полный вкус или полный год.
