### KP-QA-017 · P2 · при редактировании выбор похожей позиции не применяется

**Путь проверки.** Открыть собственный сохранённый чекин, начать редактирование, изменить заметку, нажать «Проверить пиво и сохранить». Если в выдаче сходства есть другая подтверждённая упаковка, выбрать её. **Ожидание:** человеку ясно, что именно можно изменить в существующем чекине. **Результат статической трассировки:** диалог предлагает выбрать любую карточку как при создании. Обработчик записывает выбранный positionId в объект формы, но для существующего чекина исключает positionId из PATCH и отправляет version. Сервер обновляет поля исходной позиции. Другие правки могут успешно сохраниться, хотя сделанный выбор упаковки не учитывается. У обычного создания путь POST другой.

**Доказательство и граница.** Обе ветви прослежены от кнопки до updateCheckin в коде исследуемого SHA. Интерактивное воспроизведение с двумя кандидатами на экране редактирования остаётся открытым. [Трассировка файлов и строк](evidence/final-edit-position-trace.txt). Связь с F1, FR-044 и правилом positionId в §3 ТЗ. **Предлагаемое исправление S:** в режиме редактирования показывать текущую позицию как закреплённую и убрать кнопку выбора альтернативной упаковки. Для создания оставить выбор кандидата. Проверить, что изменение текста сохраняется у прежнего positionId. Изменение серверного контракта для этого не требуется.


### KP-QA-018 · P1 · несовместимое открытие хранилища в службе напоминаний на API 26

1. На поддерживаемом API 26 установить приложение и исходный тестовый APK одной сборки. Выполнить LocalStorageTest и RemindersTest. В EditorOfflineTest дойти до повторного открытия сохранённого черновика.
2. Ожидание — SQLite-хелпер открывается и закрывается на минимальном поддерживаемом Android. Факт — все три класса падают с `ClassCastException: AccountStore cannot be cast to java.lang.AutoCloseable`. В редакторе предыдущие assert уже проверили текст, упаковку, null-оценку и изоляцию черновика.
3. Причина — AccountStore наследует SQLiteOpenHelper. В Android 8.0 этот класс не объявляет AutoCloseable. Android 13 объявляет. В APK, скомпилированном с API 35, вызов Kotlin use выполняет это приведение. В исполнительном пути ReminderJobService тот же вызов стоит до проверки владельца и notify. Служба перехватывает Exception без сообщения и завершает job. Планирование через JobScheduler само по себе дефект не выявляет.
4. F8, минимальная версия Android, регрессия F1/F2. Ошибка приведения воспроизведена на устройстве трижды в разных путях тестов. Влияние на доставку API 26 установлено трассировкой действующей службы; отдельный end-to-end показ системного уведомления API 26 не зафиксирован.
5. Размер S. В следующем этапе обеспечить совместимое закрытие хранилища (например, явный try/finally с close). Проверить уже существующую SQLite-базу и фактическую отложенную доставку на API 26 и 33+. Данные мигрировать для этого не требуется.
