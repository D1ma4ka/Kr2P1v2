# П6.1 · этап 1 · «Крафтовый клуб»

Ветка: `codex/krapiva-2-p3`. Визуальный эталон — утверждённые главные экраны концепции C из набора 14 макетов. Другие экраны пока сохраняют существующую структуру П0–П6, получая общую тему и нижнюю навигацию.

## Реализовано

- Dark: графитовая основа, тёплый светлый текст и янтарный акцент. Light: молочная основа, белые карточки, тёмный текст. Расположение компонентов одинаковое. Для читаемости мелких ссылок в Light используется более тёмный янтарный цвет.
- Общие токены типографики, скруглений, цвета; локальные контурные иконки, фирменный знак, компактные карточки и кнопка чекина. Без новых сетевых библиотек, платных API и удалённых шрифтов.
- Выбор темы в настройках, сохранение на устройстве, соответствующий цвет системных иконок.
- Единые вкладки: Главная, Каталог, Коллекция, Лента, Профиль. Недоступные будущие бары/карты удалены из навигации; П7 не реализован.
- Главная после входа/восстановления сессии: приветствие, фото профиля, статистика, последняя запись с фото, запись друга с фото, лайк, переход к комментариям, друзьям и новому чекину.
- Состояния загрузки, ошибки, пустой коллекции/ленты, отсутствующего фото; отметка сохранённой копии личных данных без сети. Социальные записи и изображения не сохраняются в постоянный кэш; при уходе с экрана или в фон социальное состояние очищается.
- Переход по последней записи открывает её существующий экран. В редакторе подтверждение выхода сохраняет выбранное назначение нижней навигации.
- Пользовательские строки Android больше не содержат прежнее название раздела личных записей. Внутренние `Diary*` и API не переименованы.

Шестерёнка на главной ведёт в существующие настройки вместо неработающего колокольчика из макета. Числа и тексты приходят с сервера: данные из макета не подставляются. При наличии следующей страницы друзей показан нижний предел `50+`, поскольку API не предоставляет общее количество. Крепость не выдумывается: ответ API чекина её не содержит. На узком экране или при увеличенном шрифте кнопка чекина переносится под приветствие; содержимое прокручивается, навигация остаётся на месте.

## Совместимость

Не изменены backend, PostgreSQL, API, миграции и существующие хранилища. Сохранены вход/регистрация, профиль/приватность, каталог/поиск/сканер/предложения, чекины/редактирование/фото/черновики, коллекция/статистика/wishlist/значки, друзья/заявки/лента/лайки/комментарии. Полный повторный прогон П0–П6 не выполняется; это перечень сохранённых точек входа и кода, а не заявление о полной регрессии.

Главная использует `GET /v1/me/home`, `GET /v1/feed?limit=1`, `GET /v1/friends?limit=50`, `GET /v1/users/:id`, существующий media API и `PUT/DELETE /v1/social/checkins/:id/like`. Лайк отображается после ответа сервера. Сессии и данные изолированы прежним аккаунтным ViewModelStore.

## Проверка и артефакты

- `python3 scripts/check_foundation.py` — успешно.
- JDK 21.0.9, Android API 35, Gradle 8.11.1.
- `./gradlew --no-daemon assembleDebug assembleDebugAndroidTest lintDebug testDebugUnitTest` — успешно; 8 JVM-тестов, 0 ошибок lint, 4 предупреждения (неиспользуемые ресурсы и предложения KTX).
- Первая попытка до остановки не дошла до компиляции из-за отсутствия javac. После установки JDK исправлено обращение к Compose-цвету из Canvas сканера; повторены только незавершённые задачи. Исходные журналы сохранены.
- APK: `work/p61-stage1/krapiva-p61-stage1-debug.apk`, package `ru.krapiva.app.debug`, локальный API `http://10.0.2.2:53000/`. Это debug-сборка для эмулятора, не production/release.
- Адресный Android-тест: `ru.krapiva.app.home.HomeIntegrationTest`; результат запуска и скриншоты фиксируются после проверки эмулятора.

Для воспроизведения: запустить существующий локальный backend по инструкции проекта; подготовить PNG для тестовых фото и выполнить из корня `P61_FIXTURE_PHOTO=/absolute/photo.png node --env-file=.env scripts/prepare_p61_fixture.mjs`. Скрипт работает только с development-БД на loopback, создаёт отдельные синтетические записи и не удаляет данные. Если `work/p61-android.json` существует, следует повторно использовать его. Пароль хранится только в игнорируемом файле; в приложение фикстура не входит. Фото для текущей проверки подготовлено из утверждённого макета, загружено обычным media API двух тестовых аккаунтов. Это синтетический контент на настоящем backend.

Установить оба APK, скопировать `work/p61-android.json` в `/data/local/tmp/p61-android.json`, запустить:

```sh
adb shell am instrument -w -r -e class ru.krapiva.app.home.HomeIntegrationTest ru.krapiva.app.debug.test/androidx.test.runner.AndroidJUnitRunner
```

Тест сохраняет реальные скриншоты в `/sdcard/Download/KraPivaP3/p61-home-dark.png` и `p61-home-light.png`. Актуализирован старый account-тест: после входа он явно выбирает вкладку профиля.
