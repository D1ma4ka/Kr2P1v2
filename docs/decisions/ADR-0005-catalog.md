# ADR-0005 — P4: каталог, поиск, модерация и коды

Статус: принято для P4, 6 ноября 2026. Основание: ТЗ v1.3 FR-020…034,
FR-100/111/113/116. P3 и его стабильные UUID сохраняются.

PostgreSQL остаётся источником истины. Рассмотрены запросы по нескольким
нормализованным JOIN-полям и отдельная поисковая проекция в той же БД.
Выбрана транзакционная проекция проверенных позиций с GIN pg_trgm и B-tree
индексами сортировки: AND по нормализованным словам названия/пивоварни/стиля,
NFKC, нижний регистр, ё→е, пунктуация→пробел. Без Elasticsearch/платных API.
Проекция обновляется SQL triggers; не зависит от фоновой индексации. Порядок
newest/name/abv стабилен по UUID; cursor привязан к фильтрам. Нет OFFSET и total
на каждом поиске. Изменение сортируемого поля между страницами требует refresh.

Новая БД пуста. Только пользовательское предложение с источником; автор видит
свою очередь, остальные — только verified. Принять/отклонить/объединить может
активный moderator/admin, роль проверяется сервером. Accept — транзакция с
блокировкой предложения, проверкой GTIN и кандидатов в дубли. Совпадение требует
явного решения модератора, не автоматического слияния. История решений в SQL.
Разные упаковки/объёмы/варианты остаются отдельными positionId. Brand — поле
выпуска, не подмена brewery. Неизвестные данные остаются null.

Слияние verified-позиций сохраняет старый UUID как alias, переносит checkins,
wishlist (с удалением дубликатов), GTIN и ссылки предложений в одной транзакции.
Цепочки alias схлопываются; карточка по старому ID возвращает canonicalId и
requestedId. Не удалять старую позицию. Права и статистика P5 используют canonical
ID. Произвольные циклы не создаются API; слияния сериализуются advisory lock.

EAN-8/UPC-A/EAN-13/GTIN-14 проходят checksum и padding до GTIN-14. UPC-E
раскрывается клиентским ZXing в UPC-A. QR не распознаётся как товар: отдельное
UNSUPPORTED_QR, никакого запуска URL. Unknown ≠ non-beer. Non-beer возвращается
только при отдельном подтверждённом решении модератора с источником.

Каталожное фото допускается лишь как собственная нормализованная upload с
явным подтверждением прав и источником, затем одобрением модератора. Внешние
URL картинок не скачиваются. Чтение approved assets доступно авторизованным
клиентам при связи с verified карточкой; удалённые/hidden закрыты сервером.
При отсутствии изображения — оригинальный брендовый placeholder.

Android: CameraX + встроенный ZXing (без runtime model download/платных SDK),
permission только при входе в scanner; release analyzer/frame/provider по lifecycle.
Read-cache ограничен и привязан к аккаунту, очищается существующим logout.
Контракт OpenAPI общий для Android/iOS, не содержит Android-specific identity.

Миграция 004 аддитивна; перед применением к существующей среде — backup runbook.
Откат: вернуть прежний binary только после согласования совместимости, восстановить
SQL+media backup в отдельную БД. Старые checksum migrations не редактировать.
Публикация, production, роли реальных пользователей, P5 не входят в эту работу.
