# ADR-0006 — личный дневник, оценки и статистика P5

7 ноября 2026. ACCEPTED для P5, ТЗ v1.3 §3/4/15/16.

Расширяем существующие checkins/checkin_media/tags/wishlist, не дублируем P2.
Миграция007 добавляет только индексы и словарь субъективных вкусовых тегов:
«Цитрусовый», «Хвойный», «Фруктовый», «Цветочный», «Солодовый», «Карамельный»,
«Кофейный», «Шоколадный», «Дымный», «Кислый», «Горький», «Пряный». Это варианты
выбора пользователя, не приписанные пиву факты. Не более12 tags и4 own images.
Фото/теги/поля записываются одной транзакцией с optimistic version; retry create
с UUID идемпотентен, повторная осознанная дегустация использует новый UUID.

Активные личные чекины: deleted_at/hidden_at IS NULL, независимо от повторов.
Уникальные = COUNT(DISTINCT position_id); serving format не создаёт позицию.
Merge P4 меняет ссылки транзакционно; расчёты выполняются по текущим SQL данным,
поэтому ни счётчики, ни диаграммы не зависят от устаревших денормализованных totals.
Личная история сохраняет ссылку даже при снятии позиции с проверки; создание
разрешено только по verified каталогу. Диаграммы стилей/пивоварен считают уникальные
positionId, неизвестный стиль отдельно. Histogram считает все чекины,20 bins,
NULL отдельно. Средняя = SUM(rating_quarters)/(4*COUNT(rating_quarters)), NULL
при отсутствии оценок; API отдаёт sum/count/average, UI округляет HALF_UP до2 знаков.
Статистический ответ — один SQL snapshot. Отображение не усредняет средние.

Агрегаты карточки: personal отдельно от visibleToViewer. Второй включает только
активные чекины verified позиций/пивоварен активных пользователей, доступные
просматривающему: свой или разрешённый одновременно profile и checkin visibility
(public либо friends с реальной взаимной friendship). Не выдаём private totals
за глобальные. Авторский дневник и редактирование остаются owner-only; social P6.
Media direct URL применяет те же checkin/profile/status ACL. Hidden/deleted records
и suspended users не дают другим доступа. Отвязанные фото остаются owner-private;
удаление файла — существующий media DELETE после отвязки, не удаление чужих данных.

Date filters ISO8601 включительно, UTC timestamps, недопустимые даты отвергаются.
Diary сортируется по occurredAt либо rating (NULL передаётся как sentinel−1),
последовательный keyset+UUID; курсор привязан к нормализованным фильтрам/сортировке.
Concurrent изменения требуют refresh (нет snapshot cursor promise). Wishlist
идемпотентный PUT/DELETE, одна пара user+canonicalPosition. Разные SKU не схлопываем.

Android кеш ограничен и зашифрован существующим Keystore, TTL24h; logout очищает
данные/черновики и отменяет scope. Черновик сохраняется явно, остаётся редактируемым
локально и имеет «Не отправлено» до подтверждения HTTP; автоматическая публикация
не реализуется без отдельной проверки SHOULD. Retry с тем же UUID не удваивает
чекин после потерянного подтверждения. После write кеш дневника/агрегатов
инвалидируется, данные читаются заново; offline помечает возможную устарелость.
Venue text допустим до P7; ссылка на verified venue возможна из существующей БД,
карточка показывает только сохранённые атрибуты. Карта/каталог мест — отдельный P7.
Транзитивные merge сериализованы существующим advisory catalog lock220024:
create/wishlist берут shared, moderator merge — exclusive, не блокируя друг друга
для независимых обычных creates. Owner-only checkin-request lookup позволяет
восстановить результат потерянного HTTP acknowledgement до новой отправки.
API: нейтральные JSON/UUID/quarter integers для Android и будущего iOS.
