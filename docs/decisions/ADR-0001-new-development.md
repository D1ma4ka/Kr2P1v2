# ADR-0001 — Разработка 2.0 с нуля и сохранение истории

- Дата: 2026-11-04.
- Статус: принято в рамках текущего запроса владельца и ТЗ §1.2.

## Контекст

`AGENTS.md` описывает прежний приоритет аудита APK и допускает изменение этого
приоритета пользователем (§5). Текущий запрос требует разработки приложения по
готовому ТЗ с P0. В актуальном `main` находятся только README и AGENTS.
Ветка recovery содержит документацию и Python-инструмент аудита, но не
производственный клиент/сервер; её наличие не требует слияния.

## Альтернативы

1. Продолжить восстановление старого APK: не отвечает текущему запросу,
   не даёт новой серверной социальной сети, требует отсутствующих материалов.
2. Разработка с нуля по ТЗ, с сохранением истории: соответствует запросу,
   позволяет проверять новые вертикальные сценарии и происхождение каталога.

## Решение

Выбран вариант 2. Рабочая ветка создаётся от `main` на
`634feca5d14ed0463d9e6ef7268be1b9e23c48ef`. `AGENTS.md` не редактируется.
Очистка активных legacy-файлов — NO-OP: таких файлов нет. Архивные ветки не
сливаются, не удаляются, история не переписывается. Старые бинарники и данные
не используются даже как seed новой production-базы.

## Последствия и проверка

Аудит старого APK не блокирует новую разработку; он не объявляется выполненным.
Прежние свойства приложения не подтверждены текущим исследованием.
P0 проверяет сохранность AGENTS и перенесённых документов через
`python3 scripts/verify_p0.py`. Реализация всех продуктовых требований остаётся
INCOMPLETE до подтверждающих сборок и функциональных тестов.
