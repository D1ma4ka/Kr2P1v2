# ADR-UI-NAVIGATION — навигация целевого приложения

Дата: 2026-11-04. Статус: инженерное решение для реализации P3–P7.
В P1 существует только стартовая UI-основа; таблица ниже — план маршрутов,
а не заявление, что 22 экрана уже реализованы.

## Сравнение

A: «Лента / Поиск / + Чекин / Бары / Профиль». Каталог и сканер — в поиске,
дневник и wishlist — через профиль, создание чекина требует выбора позиции.
Плюс: бары видны сразу. Минус: действие «+» смешано с разделами, дневник глубже.

B: «Каталог / Дневник / Лента / Профиль». Сканер/предложение/бары — из каталога,
wishlist/значки/настройки — из профиля, создание чекина из карточки позиции.
Плюс: четыре равноправных раздела и прямой доступ к дневнику, понятный back stack.
Минус: бары на один переход глубже. **Выбран B**; это не меняет MUST-сценарии.

## Полная карта доступа

| Экран | A: вход | B: выбранный вход |
|---|---|---|
| S-01 Splash/18+ | запуск | запуск |
| S-02 Регистрация/verify | S-01 | S-01 |
| S-03 Вход/reset | S-01 | S-01 |
| S-04 Каталог | Поиск | Каталог |
| S-05 Позиция | Поиск/лента/дневник | Каталог/лента/дневник |
| S-06 Сканер | Поиск | Каталог |
| S-07 Предложение | Поиск/unknown scan | Каталог/unknown scan |
| S-08 Чекин | + → выбрать позицию; S-05 | S-05 / редактирование из S-09 |
| S-09 Дневник | Профиль | Дневник |
| S-10 Один чекин | S-09/S-11 | S-09/S-11 |
| S-11 Лента | Лента | Лента |
| S-12 Люди/друзья | Лента/Профиль | Лента/Профиль |
| S-13 Свой профиль | Профиль | Профиль |
| S-14 Чужой профиль | S-10/S-12 | S-10/S-12 |
| S-15 Редактор профиля | S-13 | S-13 |
| S-16 Уникальные позиции | S-13 | S-13 |
| S-17 Wishlist | S-13/S-05 | S-13/S-05 |
| S-18 Значки | S-13 | S-13 |
| S-19 Бары/места | Бары / выбор в S-08 | Каталог → Бары / выбор в S-08 |
| S-20 Настройки | S-13 | S-13 |
| S-21 Жалоба | S-10/S-14 | S-10/S-14 |
| S-22 Admin | Отдельные защищённые API | Отдельные защищённые API |

У каждой вкладки сохраняется стек. Выход со сканера возвращает в каталог;
неизвестный код не создаёт позицию без отправки заявки. Сохранение чекина
подтверждается только сервером. Скрытые записи и media проверяются сервером.
Wishlist и уникальные позиции остаются разными коллекциями. Таблица будет
дополняться реальными route/ViewModel/endpoint/test при реализации этапов.
