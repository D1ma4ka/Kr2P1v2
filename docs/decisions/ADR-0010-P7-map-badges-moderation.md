# ADR-0010 — П7: карта, достижения и модерация

10 ноября 2026. П7 разрешён прямой командой владельца. Основание — `e8f4ba6` (кандидат П6.1; device/visual acceptance ещё PENDING). Новый рабочий checkout не создаётся, ветка `codex/krapiva-p7`. П8, расходы и deployment не разрешены.

## Карта

MapLibre Native Android **11.13.5**, BSD-2-Clause, SDK адаптирован за Android-компонентом. Yandex MapKit рассмотрен, но ключ/условия регистрации сейчас не настроены, покупка и регистрация платного доступа не выполняются. MapLibre не требует платного ключа. Maven POM и официальный source JAR проверены через TLS/checksum; лицензия POM: https://repo.maven.apache.org/maven2/org/maplibre/gl/android-sdk/11.13.5/android-sdk-11.13.5.pom.

Для ограниченной ручной dev-проверки — HTTPS `tile.openstreetmap.org/{z}/{x}/{y}.png`, без bulk/prefetch/offline downloads. User-Agent идентифицирует KraPiva, attribution постоянно виден; HTTP cache сохраняет ETag/Expires/Cache-Control, bounded disk cache. Политика проверена по исходнику OSMF: https://github.com/openstreetmap/owg-website/blob/master/policies/tiles.md. Это best-effort сервис без SLA, **не production CDN**. Release/staging требуют явно выбранного тайлового шаблона и attribution, бесплатность/доступность в РФ не обещаются без реальной проверки.

Тайловый URL конфигурируется отдельно от API, MapLibre HTTP client не получает токены аккаунта. Ошибки тайлов/SDK дают видимый статус и список. Геолокация optional: разрешение только по действию «Моё местоположение», ручной город работает без неё. SDK обрабатывает жесты/zoom, GeoJSON-source clustering и раскрытие кластера; API выдаёт только подтверждённые координаты текущего bbox. Map/list используют одинаковые фильтры. Map-response ограничен 500 точками + `truncated`; при превышении UI предлагает увеличить масштаб. Список — keyset pagination, cursor привязан к фильтрам/bbox. Нет скачивания всех заведений России на клиент.

Настоящие бары/фото не выдумываются и не импортируются из старых материалов. Production seed пуст. Пример Craft Republic из ТЗ без внешнего подтверждения допустим только как явно помеченная синтетическая fixture в изолированной dev/test БД; координаты fixture не выдаются за проверенные координаты настоящего бара. Такие объекты отсекаются production API.

## Десять правил

ТЗ не задаёт точные пороги; `PROJECT_DECISIONS.md` прямо оставляет версионируемые правила разработке П7. Следующая десятка — **инженерное решение v1, не исторически восстановленные правила**. Нет заданий выпить объём/за срок, streak или поощрения частоты употребления.

| Метрика | Цель | Название | Условие |
|---|---:|---|---|
| checkins | 1 | Первая история | Один действующий чекин |
| positions | 3 | Исследователь | Три разные подтверждённые позиции |
| positions | 10 | Коллекционер | Десять разных подтверждённых позиций |
| styles | 3 | Три стиля | Три известных стиля среди разных позиций |
| styles | 5 | Палитра вкусов | Пять известных стилей |
| breweries | 3 | Знакомство с пивоварнями | Три пивоварни |
| breweries | 5 | География пивоварен | Пять пивоварен |
| notes | 3 | Автор заметок | Заметки к трём разным позициям |
| photos | 3 | Фотоистории | Действующие фото к трём разным позициям |
| venues | 2 | Знакомые места | Два разных подтверждённых заведения |

Правила data-driven, progress считается сервером из текущей истории без deleted/hidden контента и неподтверждённого каталога; unknown styles не приписываются. Notes/photos считаются по distinct positionId, повтор A,A не даёт ложного прогресса разнообразия. После удаления/модерации/merge пересчёт отзывает утратившие основание значки и pins. Reconciliation идемпотентна, выполняется перед подтверждённым чтением значков/статистики и изменением pins; нет отдельного фонового сервиса. Максимум 3 pins и порядок проверяет сервер под user lock; другой клиент читает ту же БД. Чужой профиль может раскрывать только добровольно закреплённые earned badges после проверки profile ACL, не весь приватный прогресс.

## Модерация и данные

Совместимая миграция расширяет существующие venues/badge_rules/reports/audit_events, не заменяет таблицы. Локальный backup перед применением. Карточки заведений имеют provenance координат/фото, version и явный testOnly. Нет вымышленных рейтингов: возвращаются только вычисленные viewer-visible агрегаты существующих чекинов.

Жалобы — idempotent client UUID, проверка доступности публичного subject и rate limit. Moderator/admin решения hide/restore/dismiss сохраняются с audit; скрытие проверяется действующими ACL feed/direct/media API. Для позиции скрытие использует существующий непубличный status=rejected (схема не допускает hidden); отличать временное скрытие от отклонения позволяет hold. Отдельный hold хранит прежнее состояние, чтобы restore не обходил deleted/deletion-request и не превращал pending/merged объект в подтверждённый. Операции управления ролями доступны только admin и не позволяют саморазжалование; роль проверяется сервером. Секреты/PII не выводятся в общие логи.

## Проверка

Реальные SQL/API tests: bbox/antimeridian/filter/cursor/лимит, отсутствие непроверенных координат и production testOnly; все 10 badge rules, replay/revocation/3 pins/concurrency; публичный report→hide→API/media denial→restore и audit/roles. Android JVM — геометрия viewport/навигационные данные; сборка/lint/unit; SDK/device жесты/кластер/тайлы/permission и screenshots отмечаются по фактическому выполнению, не по компиляции.
