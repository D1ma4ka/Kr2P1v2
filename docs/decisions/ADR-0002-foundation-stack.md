# ADR-0002 — стек основы Android и сервера

Дата: 2026-11-04. Статус: принято для P1 разработчиком в рамках ТЗ §7.2;
не является утверждённым владельцем тарифом или разрешением на production.

## Контекст и альтернативы

Нужны нативный Android, небольшой модульный монолит, транзакционные данные,
HTTP JSON/OpenAPI, локальная проверка и размещение на обычном российском Linux.
В исходном репозитории нет кода, который требовал бы конкретного серверного языка.

| Критерий | Kotlin/Ktor + PostgreSQL | TypeScript/Fastify + PostgreSQL |
|---|---|---|
| Язык команды | Общий язык с Android | Второй язык; контракт OpenAPI обязателен |
| Сборка в текущей среде | Нужны полный JDK, Gradle и JVM-зависимости | Node 24 и npm уже доступны; npm lockfile |
| Эксплуатация | JVM, настройка heap, зрелые библиотеки | Один Node-процесс, строгая JSON schema validation |
| Безопасность | Зависит от конфигурации и server-side ACL | Те же требования; никаких доверенных client-side ролей |
| Поддержка | Kotlin/JVM и Gradle для двух частей | Независимый server pipeline, небольшой набор npm-зависимостей |
| Стоимость | Требуется замер heap/CPU на выбранном VPS | Требуется замер RSS/CPU; экономия не заявляется без сравнения |

## Решение

Backend: **Node.js 24 LTS, TypeScript, Fastify 5**, ESM, модульный монолит.
Домен и доступ к данным будут отделены от HTTP-обработчиков. P1 реализует только
конфигурацию, запуск/остановку HTTP и `GET /health/live`; этот endpoint проверяет
живость процесса, **не** готовность БД/SMTP/социальных функций. Неизвестные URL
возвращают настоящий 404. API данных и OpenAPI появятся в P2.

В P2 планируется PostgreSQL: FK, UNIQUE, транзакции, SQL migrations; конкретная
версия, клиент, хранилище медиа и SMTP transport фиксируются вместе с их
реальной интеграционной проверкой. Сейчас эти зависимости не устанавливаются.
Микросервисы, брокер и платные managed services не вводятся.

Android: Kotlin 2.1.20, Compose BOM 2025.04.01, Material 3, minSdk 26,
compileSdk/targetSdk 35, AGP 8.9.2, Gradle 8.11.1, JDK 21. Закрепляем
совместимую сборочную связку, а не динамические `latest`-версии. Требования
targetSdk магазина перепроверяются перед P9. Идентификатор новой установки:
`ru.krapiva.app`; debug имеет суффикс `.debug`. Это инженерный выбор namespace,
не заявление о владении доменом. Старый package/подпись не наследуются.

## Проверка и последствия

Backend: clean npm install из lockfile, typecheck/build, тесты по настоящему
локальному HTTP, SIGTERM/shutdown и проверка зависимостей. Android: Gradle
wrapper с checksum, assembleDebug + lintDebug. Подробные результаты — P1 report.
Версии npm-библиотек закреплены в package.json/package-lock.json.
Наличие исходников не доказывает работоспособность до этих проверок.

Все сетевые сервисы P1 локальные; hosting/домены/почта не покупаются.
Плановая единица развёртывания — API-процесс + PostgreSQL + media storage,
но размер VPS и рублёвый бюджет требуют измерений и решения владельца.
Нужно поддерживать два языка и согласованность контракта; это осознанная цена
независимой сборки сервера. Пересмотр стека оформляется новым ADR.
