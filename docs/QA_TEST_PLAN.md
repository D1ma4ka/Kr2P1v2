# План проверки KraPiva 2.0

Базовые источники: ТЗ §10, [52 исходных пункта](checklists/ACCEPTANCE_CHECKLIST.md),
[матрица требований](REQUIREMENTS_MATRIX.md). Документ описывает будущие
проверки; все продуктовые прогоны пока NOT RUN. Результаты P0 отдельно
в [отчёте этапа](stages/P0.md).

## Уровни и доказательства

- Domain/unit: rating 1..20 или null, A/A/B, удаление, servingFormat,
  GTIN/checksum, friendship state machine, pin limit, поисковая нормализация.
- Backend integration: настоящая SQL БД, FK/транзакции/миграции, restart,
  идемпотентность и конкурирующие запросы, SMTP-приёмник с чтением письма,
  токены/TTL/rotation/logout/reset, отказ для чужого userId.
- Media/security: реальная загрузка и чтение по правам, удаление EXIF/GPS,
  неверный MIME/oversize/decompression bomb, SSRF/SQLi/IDOR, rate limiting,
  отсутствие секретов в ответах и логах, удаление и retention.
- API contract: OpenAPI против реального сервера, error codes и pagination.
- Android: экран доступен из реальной навигации, Compose states/TalkBack/back,
  offline/reconnect/cache/logout, камера и photo picker, разные размеры/шрифт.
- Operations: чистая сборка и CI, лицензии, DB+media backup и фактический restore
  в отдельное тестовое хранилище. Нельзя проверять restore поверх production.

Тестовые U1/U2/U3 используют синтетические данные; каталог тестов отделён от
production. Нужны две независимые сессии и третий субъект без прав.
В E2E нельзя заменять API/SMTP/SQL готовыми JSON-ответами. Моки разрешены
только явно отмеченным unit/dev тестам, не доказывают E2E.

## Дополнительные обязательные негативные случаи

1. Удаление B снижает unique; удаление одного повтора A — нет; смена подачи
   не создаёт позицию; merge alias не теряет историю и не дублирует wishlist.
2. Приватный/скрытый/удалённый чекин недоступен через feed, ID, комментарии,
   reactions, media, thumbnail и чужие агрегаты после изменения privacy.
3. Запрос к чужому объекту не изменяет его; модератор и обычный пользователь
   имеют разные права. Отозванная сессия не проходит после logout/reset.
4. Пятая фотография и четвёртый badge pin отклоняются сервером; повтор или
   гонка запросов не обходят ограничения. Оценка null не попадает в среднее.
5. Разрыв дружбы, удаление аккаунта, скрытие контента и повторная отправка
   не возвращают запрещённое через старый курсор или кэш другого аккаунта.

## Учёт фактических прогонов

Статусы прогонов: PASS/FAIL/BLOCKED/NOT RUN. Для PASS необходимы команда,
версия среды, commit SHA, код выхода и отчёт. Для manual — устройство,
шаги и наблюдаемый результат. Наличие файла теста не равно успешному прогону.
На физическом устройстве ничего не проверено. Performance baseline §10.2
пока предложение; пороги не считаются достигнутыми без измерения.
