## 3. Цель и границы П6.1

Реализовать утверждённый пользовательский интерфейс **существующего Android-приложения** с полноценными светлой и тёмной темами, сохранив функциональные сценарии и архитектуру П0–П6.

Обязательно:
1. Сначала инвентаризировать действующие Compose-экраны, навигацию, `designsystem/Theme.kt`, используемые компоненты, ресурсы, состояния загрузки/ошибки/пустого экрана; сопоставить с макетами.
2. Ввести согласованную тему Light и сохранить Dark; централизовать семантические цветовые/типографические/spacing-токены. Обе темы реально доступны в работающем Android UI (переключение темы должно сохраняться после перезапуска; способ выбора согласовать с доступным экраном настроек и макетами).
3. Переработать только существующие и утверждённые макетами экраны и их компоненты. Сохранить маршруты, действия, валидации, состояние Compose при recreation, работу с фотографиями, формами и сетевыми ошибками.
4. Использовать настоящие API и данные; не заменять backend заглушками, случайными цифрами, несуществующими сортами или demo-чекинами. Не затрагивать PostgreSQL, миграции, OpenAPI и серверную приватность без отдельного технически обоснованного согласования.
5. Не начинать функциональность П7 (бейджи, карта, заведения), не переделывать завершённые этапы и не начинать iOS-трек. Не удалять исторические исходники и отчёты.

## 4. Критерии приёмки П6.1

- Инвентаризация **14** референсов: для каждого сохранены имя/путь, тема, соответствующий экран/компонент и статус использования. Количество реальных экранов не выводить из количества картинок автоматически.
- Скриншоты **из реального эмулятора/устройства** в обеих темах, сопоставленные с утверждёнными макетами; реальные состояния, без презентационных подмен. Отклонения записаны явно.
- Оба варианта темы читаемы: контраст/кнопки/поля/иконки/статус-бары; корректные keyboard insets, 320dp, font scale, TalkBack/reduced-motion и пустые/ошибочные/offline состояния. Непроверенные физические сценарии честно пометить NOT RUN.
- `assembleDebug`, `lintDebug`, `testDebugUnitTest` PASS; ограниченный Android instrumented набор для затронутых маршрутов PASS; регрессия auth, каталога, чекинов и социальной сети. Ошибки диагностировать, не запускать бесконечные повторы.
- Commit/push рабочей ветки, screenshot manifest, отчёт по файлам и проверкам, обновлённые `docs/PROGRESS.md`, матрица требований и дизайн-документы. После отчёта **STOP** до следующего разрешения владельца.
