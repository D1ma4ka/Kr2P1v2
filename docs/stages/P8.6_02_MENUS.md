# P8.6.2 · Меню заведений

Миграция `015_venue_menus.sql` добавляет черновик и одну опубликованную редакцию для существующего `venues.id`. Секции принадлежат редакции. Одна упаковка занимает одну строку по `positionId` в каждой редакции. Разные упаковки выпуска могут иметь разные цены. Максимум 40 секций и 250 позиций. Цена указывается в единицах валюты с точностью до двух десятичных знаков; пара цена/валюта обязательна при задании цены. Объём и способ подачи опциональны. Источник указывает оператор, идентификаторы обновившего и выдавшего права хранятся на сервере.

| Метод и путь | Действие |
|---|---|
| GET /v1/venues/:id/menu | Возвращает опубликованный снимок, `menu:null` до публикации, 404 для недоступного места. Доступ как в справочнике мест, по токену. |
| GET /v1/venues/:id/menu/draft | Возвращает черновик уполномоченному пользователю. |
| PUT /v1/venues/:id/menu/draft | Создаёт или заменяет черновик, секции и позиции одним пакетом. Для первой записи expectedRevision=0. Если позицию исключить из пакета, она уйдёт из черновика. |
| PUT /v1/venues/:id/menu/draft/items/:positionId | Добавляет или заменяет строку в существующей секции. В теле expectedRevision и поля предложения. |
| DELETE /v1/venues/:id/menu/draft/items/:positionId?expectedRevision=N | Удаляет строку черновика. |
| POST /v1/venues/:id/menu/publish | Публикует черновик целиком, включая пустой. В теле expectedRevision. |
| PUT /v1/moderation/venues/:id/menu/operators/:userId | Модератор или администратор назначает owner/operator из активных аккаунтов. role=null отзывает доступ. |

Изменения одного места сериализуются блокировкой строки venues, версия черновика защищает от перезаписи. Публикация заменяет снимок целиком, гости видят предыдущий до commit. Каталожные позиции должны быть верифицированы. Слитый ID требуется заменить действующим ID в черновике. Чтение исключает позиции и пивоварни, потерявшие верификацию. Оценка вычисляется тем же правилом видимости, что в статистике позиции, а флаг tried относится к действующим чекинам только владельца сессии. Полный ответ приватный, с запретом HTTP-кэширования. Схемы в [OpenAPI](../api/openapi.yaml).

Android открывает «Меню» из существующего места. На карточке видны цена, объём (при отсутствии объёма предложения используется известный объём упаковки), пивоварня, стиль, крепость, оценка и доступность. Карточка каталога открывается по ID позиции, создание чекина получает также заведение. Копия берётся из штатного шифрованного кэша аккаунта при сетевой ошибке или 5xx, пока срок хранения 24 ч не истёк. Публикация старше 24 ч сопровождается пояснением о возможном изменении наличия. Наличие определяется публикацией оператора.

Проверен серверный контракт на изолированном PostgreSQL: два места, две упаковки, права, одновременные изменения, скрытие черновика, рейтинг с приватностью, отсутствие публикации, пустая редакция и отзыв доступа. В [передаче](P8.6_HANDOFF.md) указаны результаты общих проверок и ручные сценарии.
