## A6

Миграция 012 добавляет nullable users.handle с проверкой формата/lowercase и
уникальным индексом. UUID, hashes, сессии, связи, media и черновики не меняются.
Старые клиенты без handle остаются совместимыми: после входа предлагается
выбор, «Позже» открывает прежний аккаунт; выбор также доступен в профиле.
Новые Android-регистрации передают handle, displayName изначально равен ему;
отображаемое имя редактируется отдельно по-прежнему, в том числе на русском.
Выбранный handle закрепляется за аккаунтом (смена не входит в текущий объём).

Проверка формата в Android/сервере, нормализация только ASCII lowercase,
конкурентная уникальность обеспечена БД. GET /v1/auth/handles/:handle даёт
доступность с auth budget; PUT /v1/me/handle — выбор старым пользователем.
Резервные служебные имена и явные оскорбления блокирует версионированный
denylist handles.ts; это базовая политика, не исчерпывающая модерация языка.
Публичные профили, друзья, feed, комментарии показывают handle; поиск ищет
имя и @handle с прежними ACL. Никаких новых связей вместо UUID нет.
OpenAPI обновлён; backend следует обновлять после применения 012.

Адресные HTTP/SQL/Mailpit/upgrade тесты: 5/5 PASS, включая гонку регистрации
case-insensitive, реальные письма/OTP, старый hash, сессии, чекин и дружбу,
приватность поиска и отдельное редактирование displayName. Android build,
test APK, lint PASS; JVM включает правила формата. UI/runtime NOT RUN.

## A7

POST /v1/auth/login принимает прежний email либо новый identifier; передача
обоих отклоняется. Email/handle/@handle находят одну users.id и используют
тот же scrypt-v1, sessions, verified/status проверки и auth budgets. Ошибки
не раскрывают наличие аккаунта. Восстановление по-прежнему по email.
Android показывает «Почта или никнейм», без автозамены пароля. Подтверждение
почты со входа доступно для email, а не для @handle.
Адресные HTTP/SQL/SMTP тесты 4/4 PASS: все способы входа дают прежний ID,
старый email contract работает, неверные данные дают общий 401.
