# P8.6.6 · KraPiva Advisor

В меню появился блок «Что мне попробовать?» с тремя режимами, первыми тремя результатами и экраном всех рекомендаций. Режим «Новое для меня» исключает опробованные `positionId`. «Удиви меня» повышает позиции со стилями и пивоварнями, редко встречающимися в истории. Каждый результат показывает фактические характеристики и объяснение по запросу, открывает карточку и редактор чекина.

## Данные и обновление

`GET /v1/me/advisor-history` возвращает одну согласованную выборку из PostgreSQL. Сервер выбирает активные записи владельца сессии по `occurred_at DESC, id DESC LIMIT 100` через существующий индекс дневника. Ответ содержит ID записи, позиции, пивоварни и стиля, время, оценку в четвертях и признак первого действующего чекина позиции. Этот признак учитывает всю историю владельца, включая записи за границей окна. Тело, заметки, фото, сведения профиля и чекины других пользователей за пределы запроса не выходят.

Кандидаты берутся из доступных позиций опубликованного меню с учётом выбранных фильтров. Пакет меню содержит `tried` по истории пользователя и отдельный `publicAverageRating` только из публичных чекинов публичных активных профилей. Личный и доступный аудитории рейтинги для сравнения не участвуют в Advisor. Вес крепости отсутствует.

Персональный подбор загружает историю напрямую, отдельно от кэша каталога. Число полученных чекинов видно на экране. Для 0–2 записей и недоступного сервера предусмотрен нейтральный порядок по публичному рейтингу с явным пояснением. При наличии только кэша меню отображается его происхождение. Выход, повторный вход и смена аккаунта меняют идентификатор сессии. Запоздалые ответы старой сессии не используются и не могут восстановить её токен. При входе и возврате в меню запрашиваются свежие снимки, а кнопка обновления доступна при изменении истории на другом устройстве. Смена фильтра пересчитывает кандидатов на `Dispatchers.Default`.

## Формула LocalDiscovery

Новое ранжирование вызывается через `LocalDiscovery.advise`, коэффициенты заданы в `AdvisorWeights`. Существующий подбор экрана «Открытия» использует прежний контракт.

Для каждой пивоварни, стиля и позиции считаются количество уникальных `positionId` и недавность. Индекс последнего чекина в окне начинается с нуля, вес недавности равен `R = 100 − floor(индекс/2)`. Для оценок внутри одной позиции используются три последних чекина с множителями 100%, 25% и 10%. Пропущенная оценка не даёт знакового вклада. Вклад позиции ограничен двумя повторными наблюдениями сверх первого. При оценке `q` в четвертях балла рассчитывается суждение группы `J = trunc(100 × sum(w × (q−12)) / (sum(w)+200))` по оценённым наблюдениям. `w` — недавность после множителя повтора.

| Слагаемое | Баллы |
|---|---|
| Публичная оценка | `round(10 × рейтинг)`. При отсутствии оценки вклад пропускается. |
| Новизна | Для непробованной позиции `50 + floor(50 × число первых чекинов / N)`. Для опробованной вклад равен нулю. |
| Привычный выбор | `18 × min(уникальных пивоварни,30) + 6 × min(повторов пивоварни,12) + floor(R пивоварни/2) + 11 × min(уникальных стиля,15) + floor(R стиля/3)`. Неизвестные группы дают ноль. |
| Необычный выбор | `20 × (15 − min(уникальных стиля,15))` для известного каталогу стиля и ещё 70 для пивоварни вне окна. |
| Личные оценки | `min(600, 3 × J пивоварни + J стиля + 2 × J позиции)`. Низкие оценки снижают балл независимо от частоты. |

Итог — публичная оценка, новизна, личные оценки и слагаемое режима. «Новое для меня» использует привычный выбор на непробованных позициях. При нейтральном выборе базовый балл даёт только публичная оценка. Для первой тройки из базового балла вычитается 700 за каждую уже выбранную позицию той же пивоварни и 100 за каждую с тем же известным стилем. Выбор выполняется последовательно, затем оставшиеся позиции идут по базовому баллу. Равенства разрешаются базовым баллом и `positionId`. Если в меню подходит меньше трёх позиций, выводится фактическое количество.

Причины используют счётчики из текущей выборки. В проверке 30/30/30/10 первая тройка представляет Zagovor, Big Village и Velka Morava, если их оценки положительные или отсутствуют. Систематически низкие оценки Zagovor снижают её приоритет.

## Приёмка

Серверный контракт проверяет границу 100, равные даты с микросекундами, двух владельцев, пустой ответ, исключение скрытого и удалённого, изменение оценки через PATCH и минимальный состав ответа. JVM-тесты покрывают 0, 1, 10, 99, 100 и более 100 записей, ограничение повторов, три режима, 30/30/30/10, отсутствие оценок, недоступную историю, отсутствие любимой пивоварни, одну подходящую позицию и воспроизводимость объяснений. Реальные результаты и открытые сценарии на Android приведены в [передаче](P8.6_HANDOFF.md).
