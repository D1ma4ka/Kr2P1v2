## Автоматические регрессии

- Backend `npm run build`, `npm run openapi` и `npm test` прошли. 49 из 49 тестов. Проверены контракт и миграции, карта, Smart Bar, каталог, авторизация, чекины и discovery.
- Android `:app:testDebugUnitTest`, `:app:assembleDebug`, `:app:assembleDebugAndroidTest`, `:app:lintDebug`. 48 из 48 JVM-тестов, без пропусков. Сквозной тест использовал декодеры и LocalDiscovery из приложения с реальным HTTP, Fastify и PostgreSQL. Обе debug-сборки собраны. Lint завершился с 0 ошибок и 14 предупреждениями.
- `scripts/verify_p0.py`, `scripts/check_foundation.py` и `git diff --check` прошли.

## Инструментальная проверка на AVD

Эмулятор запущен с программной эмуляцией CPU. На Android 15 установка приложения прервалась в системном `PackageInstaller` до завершения запуска ОС. На Android 11 оба APK установились, AndroidJUnitRunner запустил `NearbyFindsJourneyTest`. При ширине 320 dp тест дошёл до интерфейса «Находки рядом» и вызвал системный запрос геолокации. Журнал AVD подтвердил открытие `GrantPermissionsActivity`. Системный диалог «System UI isn’t responding» перекрыл кнопку отказа, и тест завершился таймаутом её поиска.

Повторный прогон на Android 11 при ширине 540 dp и шрифте 130% прошёл действия Compose в списке с выключенным разрешением. Тест выбрал город QA, радиус 3 км, пресет «Мои IPA» и сортировку по числу совпадений. В списке подтвердились 48 и 5 позиций. Общий помощник `TestEvidence` остановил визуальную проверку из-за системного диалога ANR.

В диагностическом прогоне переключение на «Карта» создало `MapView`. Проверка числовой метки завершилась по таймауту. Журнал зафиксировал ошибку DNS для тайлов OpenStreetMap и `EGL_BAD_MATCH` в программном рендерере. Последний запуск с открытием меню перед проверкой карты установил тестовый APK, но AndroidJUnitRunner не сообщил о старте за четыре минуты ожидания. Переход из списка в редактор и возврат с фильтром требуют подтверждения на устройстве. Также открыты отрисовка меток и кластеров, выбор точки, успешная геолокация, смена аккаунта на устройстве, работа после потери соединения и визуальная проверка 320 dp и обеих тем.

## Проверка в Android Studio

1. Переключиться на [рабочую ветку](https://github.com/D1ma4ka/Kr2P1v2/tree/codex/krapiva-p8.7-nearby-finds) и выполнить `git pull --ff-only`. Из каталога `android/` открыть проект в Android Studio с JDK 21, SDK 35, Build Tools 35.0.0 и вариантом `debug`.
2. Запустить локальный API по [инструкции](../DEPLOYMENT_RU.md) и опубликовать меню тестовых мест. Для воспроизведения на заранее наполненных меню использовать изолированный стенд. Из `backend/` выполнить `npm ci` и `npm run build`. Передать `TEST_DATABASE_URL` локального PostgreSQL с правом создать временную БД, затем выполнить `KRAPIVA_SMART_BAR_STAND_PORT=53000 node dist/test/smart-bar-stand.js`. Оставить терминал открытым. EOF останавливает стенд и освобождает его временную БД.
3. Debug-клиент AVD по умолчанию использует `http://10.0.2.2:53000/`. Войти в тестовый аккаунт `beta@example.invalid` с паролем `Isolated Smart Bar QA!` только на изолированном стенде. Для отдельного тестового телефона использовать `adb reverse tcp:53000 tcp:53000` и собрать debug с `KRAPIVA_DEV_API_BASE_URL=http://127.0.0.1:53000/`.
4. В «Места и карта» открыть «Находки рядом». Без разрешения выбрать город `QA`. Переключать радиусы и режимы. В обычном меню A сохранить «Мои IPA» со стилями IPA/APA, ABV 4–8%, объёмом 250–330 мл и «Не пробовал». Применить через «Мой фильтр», переключить список на карту, проверить кластер и числовую метку. Открыть отфильтрованное меню, сравнение, Advisor, карточку и редактор чекина. По возврате проверить радиус, пресет и сортировку.
5. На отдельном AVD проверить разрешённую геолокацию, отказ, выбор точки карты, потерю сети и повтор, пересоздание Activity, другой аккаунт, 320 dp, увеличенный шрифт и обе темы. Чтобы запустить автоматизированный маршрут из Android Studio, запустить `NearbyFindsJourneyTest` из `androidTest` с тем же стендом и тестовой установкой без разрешения геолокации. Аргумент инструментального прогона `locationDialog=true` дополнительно нажимает системный отказ и проверяет сообщение приложения. Аргумент `captureScreenshots=false` запускает функциональные утверждения без сбора снимков.

Запуск Kotlin и HTTP проверки вместе из `android/`:

```sh
KRAPIVA_SMART_BAR_TEST_BACKEND=/absolute/path/to/Kr2P1v2/backend \
  ./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

В этой команде требуется заранее экспортировать `TEST_DATABASE_URL`. Для полного backend-прогона из `backend/` также задать `DATABASE_URL` локального экземпляра и запустить Mailpit на портах 51025 и 58025 либо передать соответствующие `SMTP_PORT` и `MAILPIT_API_URL`.
