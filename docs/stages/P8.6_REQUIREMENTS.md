# Smart Bar · требования и приёмка

Основания — [аудит и решения](P8.6_01_ARCHITECTURE.md), [актуальное ТЗ, особенно §§15, 17 и 18](../TECHNICAL_SPECIFICATION.md). Ниже критерии будущей реализации. Синтетические данные допустимы только в изолированных тестах.

| ID | Наблюдаемое поведение | Проверка и ожидаемый результат |
|---|---|---|
| M1 | Модератор публикует реальное меню известного заведения с указанием источника. | Чтение до публикации возвращает menu=null. После первой публикации видны только переданные упаковки в заданном порядке, источник, время и revision. У соседнего места состав прежний. |
| M2 | Публикация атомарна, доступ ограничен ролью. | Обычный пользователь получает 403. Неверная позиция среди валидных, alias-дубль или 251 строка отклоняют весь пакет. При двух записях с одной expectedRevision проходит одна, другая получает 409. Повтор старого запроса сохраняет текущую редакцию. |
| M3 | Показывается только допустимый ассортимент. | После снятия позиции с публикации в каталоге очередное чтение её исключает. Скрытие заведения закрывает чтение. После публикации пустого списка видна дата и отдельное состояние. Чекины, события, wishlist сами строк меню не создают. |
| F1 | Пользователь комбинирует запрос, стиль/семейство, пивоварню, упаковку, ABV, IBU, объём и доступные персональные условия. | Два стиля × две упаковки × ABV [4,5] дают объединение внутри каждой группы и пересечение между ними. Обе границы включены; неизвестный ABV исключён, без диапазона сохранён. Сброс возвращает полный список. |
| F2 | Результат и порядок воспроизводимы на полном наборе. | Позиция за пределами первых 20 находится. При равных значениях порядок стабилен по ID. Проверить NFKC/регистр, неизвестный styleId, пустое пересечение, нулевой IBU и ошибочный диапазон. Каталог сохраняет прежние запросы и сортировки. |
| S1 | Каждая из пяти тем открывает видимое редактируемое условие. | На наборе с позициями ABV 5/5.01, IBU 25/26 и разными упаковками проверить первые три сценария. Для двух персональных тем проверить свежую историю, отсутствие оценок и недоступность второй страницы. |
| S2 | Сохранённый фильтр имеет имя и владельца. | Создать, переименовать, изменить и применить после перезапуска. После новой публикации подходит добавленная позиция. Удаление правила не меняет collections-v1; обновление поверх P8.4 сохраняет старые membership. Для другого аккаунта список правил пуст. |
| C1 | Выбор от двух до четырёх уникальных позиций одного места. | При одной кнопка сравнения недоступна, при 2/3/4 работает, пятую добавить нельзя. Банка и бутылка одного releaseId остаются двумя строками выбора; два alias одной позиции дают одну. |
| C2 | Контекст и значения сравнения устойчивы. | Смена заведения очищает выбор. При удалении строки из публикации она исчезает из выбора. Проверить ABV, IBU, объём, стиль, упаковку, пивоварню и персональный рейтинг; null, ошибка и кэш различимы. Сохранить существующее сравнение пары из каталога. |
| R1 | Вход алгоритма — до 100 последних действующих записей сессии. | Проверить 0, 1, 49, 50, 51, 100, 101 и совпадение дат на границе страниц. При 101 запись №101 по паре (occurredAt,id) исключается. Два чекина на одну позицию считаются двумя наблюдениями. |
| R2 | Персональный результат изолирован по аккаунтам. | Включить свои private-записи, исключить скрытые, удалённые и чужие (даже public). Подать курсор A с токеном B: 400. Переключиться на B во время второго запроса A: данные и причины A не появляются. После 401 или обрыва страницы 2 показать недоступность персонального блока. |
| R3 | Алгоритм v1 учитывает величину личной оценки, стиль, пивоварню, новизну и разнообразие. | Две оценки 20 и 16 в группе дают P=300. Для новой позиции известного выпуска при P(style)=300, P(brewery)=0 получить B=700. После выбора одной позиции того же стиля (иная пивоварня) скорректированный балл 600. Проверить отрицательную оценку предпочтения, null и ничью по ID. |
| R4 | Рекомендации объяснимы и доступны без внешней модели. | Перестановка входных строк при том же окне/меню не меняет top-10. Все ID принадлежат отфильтрованному меню, дублей нет. При нуле истории персональная причина отсутствует. При отказе сети каталогизированное меню с датой пригодно для обычного сравнения известных полей. |
| Q1 | Экран пригоден на поддерживаемом Android. | API 26 и 33+, две темы, ширина 320dp, шрифт 150%, TalkBack: открыть место без геолокации, найти позицию, применить фильтр, сравнить четыре позиции, вернуться. Название упаковки связано со значением и доступно озвучиванию. |
| Q2 | Цена загрузки ограничена, прежние функции сохраняются. | На 250 строках один запрос меню, без статистики для каждой строки; штатно ≤2 страницы для 100 чекинов. Для сравнения запрос статистики только для выбранных ID. Проверить существующие меню навигации, сканирование GTIN, списки, дневник и подсчёт выпуска по §18. |

Ручной релизный сценарий требует подтверждённого источника ассортимента, времени фактической публикации и согласованного тестового заведения. Без них допустим только прогон контракта на помеченных тестовых данных.
