## Вход и восстановление

Новый `/v1/auth/reset-password-code` принимает `email`, ровно шесть ASCII-цифр
и новый пароль (12–128 символов). Код хранится как scrypt hash в новой таблице
`password_reset_codes`; срок 10 минут, максимум пять атомарно сохранённых
попыток, resend не чаще минуты, успешный reset отзывает все сессии/refresh.
Android сохраняет email между экранами и предлагает повторную отправку.

Миграция `011_password_reset_codes.sql` только добавляет таблицу. Применение:
`cd backend && node --env-file=../.env dist/src/db/migrate.js` либо существующий
Compose migrate runner перед запуском обновлённого API. Старые миграции,
аккаунты и формат `scrypt-v1` не менялись. Ранее выданные 43-символьные tokens
по-прежнему принимает legacy endpoint; новые письма содержат только шесть цифр.
Каждый способ успешного reset погашает другой способ.

Вход больше не применяет требования создания нового пароля к существующему:
принимает 1–128 символов и проверяет сохранённый scrypt hash. Создание/смена
по-прежнему требуют минимум 12. Тест создаёт существующий hash с коротким
паролем, входит, выполняет reset и входит новым паролем после restart API.
Это проверка совместимости формата; аккаунт владельца в его среде недоступен.

В debug/staging видны среда и адрес API; fallback на другой сервер отсутствует.
Dev/test SMTP по-прежнему разрешает только `@example.invalid` и локальный
SMTP. Неподдерживаемый адрес объясняется сообщением, вместо общего сбоя почты.
Ответ API явно указывает локальный Mailpit; внешняя доставка не заявляется.
У Mailpit отключён reverse DNS локальных peers: до изменения новый HTTP reset
тест дважды получил SMTP 503, после изменения прошёл через реальные письма.
Это подтверждает устранение сбоя в текущей контейнерной среде; причина проблем
с внешним ящиком владельца без его сервера/SMTP не установлена.

Новый HTTP/SQL/Mailpit тест PASS: existing hash, письмо с одним шестизначным
кодом, leading zeroes, malformed/wrong email, short password, expiry,
пять параллельных неверных попыток, resend/cooldown, одноразовость,
legacy tokens, отзыв access/refresh и вход после restart.

## Пиво на загрузке

`ClubSplash` использует существующий согласованный `ClubBeer` и
`rememberLiquidAnimation`: gravity → accelerometer, low-pass, затухающая
пружина ±8°, учёт поворота экрана; без датчика — автоматическое колебание.
Подписка/цикл работают только при RESUMED и освобождаются при pause/dispose;
системное отключение анимаций и кнопка остановки соблюдаются.
Новое `reveal=false` на splash сразу показывает наполненный бокал: прежнее
наполнение за 1,8 секунды могло не успевать проявиться при быстром восстановлении.
Переход определяется только восстановлением сессии, без ожидания анимации.
На auth-формах `ClubBeer` отсутствует.

Host sensor checker обновлён: он запускает настоящий `ClubSplash` через
отдельный instrumented harness, подаёт события датчика и проверяет наклон
отрисованной поверхности. Сорокасекундное окно существует только в тесте,
в production startup задержки нет. `py_compile` checker PASS.
Runtime sensor/pixel проверки пока **NOT RUN**: нет подключённого устройства
и `/dev/kvm`; успешная компиляция тестового APK не подменяет их исполнение.
