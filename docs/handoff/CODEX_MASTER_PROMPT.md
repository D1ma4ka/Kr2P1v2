## C. Что нужно создать

**KraPiva 2.0** — современный русскоязычный нативный Android-клиент + настоящий backend на российских серверах (для production после разрешения) с пользователями 18+, каталогом пивных позиций, чекинами, профилями, социальной сетью, достижениями и барами.

### C1. Android

- Сохрани **подтверждённый выбор** Kotlin + Jetpack Compose + Material 3 как платформенную базу. Код новая реализация, не repack старой APK.
- Чистые слои UI/State/Domain/Repositories/Local/Remote, тестируемые бизнес-правила, архитектурно выделенные модули/пакеты без искусственного дробления.
- Реальные экраны: 18+ и авторизация, каталог/поиск/сканер/карточка позиции, создание/просмотр/редактирование чекина, дневник, лента друзей, люди/друзья, свой/чужой профиль, редактирование профиля, wishlist, уникальные позиции, значки, бары/места, приватность, жалоба.
- Пустые/ошибочные/офлайн/неподтверждённые/ожидающие модерации состояния; без фиктивно успешных запросов.

### C2. Backend

- **Обязательный реально работающий API** с серверной постоянной БД, авторизацией, серверной проверкой прав и приватности, реальным хранением фото, модерацией, логированием и миграциями.
- Регистрация e-mail + проверка адреса, вход, выход, сброс пароля, ограничение попыток, безопасные сессии. Для тестов допустим реальный локальный SMTP-приёмник (письма отправляются и читаются), но **не** выдавай его за production доставку почты.
- API для пивоварен/пивных позиций, поиска и предложений, GTIN новых позиций, чекинов, wishlist, друзей, ленты, реакций, комментариев, значков, баров, фото, жалоб и администрирования.
- Минимальная админ-поверхность или защищённые admin API **с настоящими операциями**: подтвердить/отклонить позицию, модерировать жалобу, завести реальный бар, просмотреть журнал решений.
- База/объектное хранилище/почта/hosting — выбирай через ADR. Исторически backend-стек **не был утверждён**. Предпочти обоснованный экономный **модульный монолит**, не микросервисы по умолчанию. Сравни минимум две реалистичные альтернативы, объясни стоимость, поддерживаемость, безопасность и способность собрать/запустить их здесь.
- Контракт API в OpenAPI, migrations, server logs с маскировкой PII/secrets, healthchecks, backup/restore staging.

### C3. Социальный продукт

Реальные два разных аккаунта U1/U2 должны уметь дружить (заявка→принятие), публиковать чекины, видеть разрешённые чекины в ленте, ставить/снимать реакции, писать/удалять собственные комментарии, видеть чужие профили по правилам доступа. Нет интернета — честно показать состояние сети. **Никаких hardcoded общих фейковых постов/«живой» ленты в production.**

### C4. Уникальная пивная позиция — центральное бизнес-правило

Не считай уникальность «пивным стилем» или усреднённым «сортом». **Уникальный объект — `BeerPosition` с постоянным `positionId`.** Например, банка пива ZAGOVOR определённого выпуска/варианта — позиция. Если официально отдельно каталогизированы две упаковки/варианта одной линейки, их `positionId` разные и **обе считаются уникальными**. Повторное посещение той же позиции не увеличивает уникальность:

- A(can0.5) → чекины 1, уникальных 1.
- A(can0.5), A(can0.5) → чекины 2, уникальных 1.
- A(can0.5), A(can0.5), A(can0.33) с отдельным `positionId` → чекины 3, уникальных 2.
- Удаление единственного чекина B уменьшает уникальные; удаление одного из повторов A не уменьшает.

**ВАЖНО:** поле подачи на чекине «кран / бутылка / банка» **не должно автоматически создавать новую пивную позицию** — уникальность определяется реальной каталогизированной сущностью. Отобрази во всём UI слово «уникальные позиции» (не подменяй «уникальными сортами»).

### C5. Каталог, штрихкод и фотографии

- **Никакой старой базы** GTIN/фото. Создай собственные модели `Brewery`, `BeerRelease`, `BeerPosition`, опциональный `BarcodeMapping`, предложения/проверки. Начало production каталога может быть пустым — при этом должны работать предложение новой позиции и модерация; не рисуй вымышленные бары/пиво как реальные.
- Камерный сканер нужен как сценарий; ищет по только что созданному **новому** каталогу. Неизвестный код → внятный «не найдено», ручной поиск/добавление с заполнением поля. Непивной код нельзя автоматически объявлять «пиво» или «непиво» без подтверждённых данных. Сканер не основание возвращать старые коды.
- Пользовательские фотографии — upload/resize/EXIF removal/ACL. Фото каталога — собственные/лицензированные, указывай происхождение.

### C6. Чекины и значки

- Оценка от 0,25 до 5,0 шагом 0,25, состояние «без оценки» отдельно; отзыв, фото (исторический максимум 4), время и место; повторы разрешены; редактирование/удаление реальны.
- Wishlist: add/remove без дублей, серверная синхронизация. Статистика по `positionId`; дополнительно стиль/пивоварня если данные реально есть.
- Стартовый набор **10 значков** с прозрачными правилами и прогрессом по настоящей истории; закрепить максимум 3. **Не использовать ботанические названия/иконки** («Первый лист» из старого приложения заменить на пивной нейтральный). Событийные значки — расширение, только с проверяемыми правилами.

### C7. Бары и карты

- Справочник и поиск **реальных** баров/заведений (без массового фиктивного наполнения), привязка подтверждённого места или честный свободный текст к чекину, открытие внешних Яндекс Карт.
- Встроенный Yandex Maps SDK только если лицензия/стоимость подтверждены; не регистрируй платный сервис без моего согласия.
- Коммерческий кабинет бара/подписки/платные меню/POS — **не часть обязательного релиза 2.0**, доработать позднее отдельной фазой. Старые 2–4 тыс. ₽/мес — сценарии финансовой модели, не утверждённый тариф.

### C8. Дизайн и бренд

Создай **новый оригинальный бренд** KraPiva: логотип, Android adaptive icon, splash и аватар-заглушка на тему **крафтового пива**, пены, бокалов, этикеток, кегов/пивоварения, барной культуры. Это не приложение про растение крапиву. Не использовать лист, стебель, ботанику как главный знак. Не копировать Untappd. Допустим новый UI при сохранении функций. Исторический референс цвета: тёмный `#111310`, светлый `#F5EEE4`, янтарный `#F4B45E`; **не обязательная** конечная палитра. Реализуй дизайн-токены, доступность, пустые/ошибочные состояния и адаптивный интерфейс. Предъяви реальные SVG/PNG и скриншоты, а не только описание будущего дизайна.

### C9. Безопасность/право/эксплуатация

- Пользователи 18+, приватность на сервере, минимизация персональных данных. Российский хостинг и проверка локализации **БД, медиа, бэкапов, логов**. Работает без VPN.
- Не вводить алкогольные челленджи на быстрое/чрезмерное употребление, запрещённую онлайн-рекламу и продвижение алкоголя. Перед открытым запуском — юридическое заключение по ПДн и рекламе алкоголя; не выдавать собственную техническую проверку за заключение юриста.
- Никогда не коммитить `.env`, keystore, пароли, токены, сертификаты или доступы. Платные сервисы, изменение GitHub permissions/visibility, деплой production, публикация магазинов, реальный релиз и merge — только после согласия по `AGENTS.md`.
