# Приёмка KraPet P10

## Повторный прогон после восстановления

На чистом стенде PostgreSQL 17.7 и Mailpit прошли backend build и 52/52 тестов. Отдельный HTTP-прогон получил 2 KC за один безалкогольный чекин с повтором, купил печенье за 1 KC и подтвердил остаток 1 KC. Сервер отклонил поля цены и баланса в покупке. После изменения цены повтор вернул прежний экземпляр, а история сохранила списание −1 KC. После проверки цена возвращена.

Через действующий импорт добавлено временное сезонное лакомство с партнёрской серией. На работающем API проверены появление, сумма, WebP по SHA-256 и истечение срока. Запись удалена. Покупка и надевание пяти вещей, размещение папоротника и повторный вход подтверждены через HTTP. Нативный повтор проверяется отдельно.

Исправлен стык `sit` → `eat`: угощение начинается в уже занятой позе у стола. После жевания следует отдельный жест вытирания рта и возвращение. 11/11 тестов рига прошли, в том числе совпадение начала `eat` с концом `sit` и возвращение в нейтральную позу для всех пяти питомцев.

## Доказательства до повторного прогона

Проверки проведены на изолированных PostgreSQL 17 и Mailpit с синтетическими данными, а также на Android Emulator API 26 при 320 dp. Исходный рабочий продукт — P8.7.2. Ветка `p10/krapet` содержит оба исходных коммита графики и развитие Android и backend.

## Выполненные автоматические проверки

- Backend: 52 теста. Регистрация и вход, схема OpenAPI, обновление исторических БД, авторизация, регрессия существующих функций, выдача питомца, начисления KC, конкурентные покупки, идемпотентность, каталог, импорт и QR.
- Android: 48 JVM-проверок, `assembleDebug`, `assembleDebugAndroidTest` и `lintDebug`.
- Риги: 11 Node-проверок геометрии, выбора спрайтов, фаз моргания и слотов на пяти питомцах. Загружены 21 описание клипа на персонажа.
- Подпись APK и выравнивание проверяются и локально, и в GitHub Actions.

## APK

[Сборка GitHub Actions с APK для эмулятора и телефона](https://github.com/D1ma4ka/Kr2P1v2/actions/runs/45891119804). Архив содержит APK, SHA-256 и SHA исходного коммита. Для локальной проверки запустите backend и пробросьте порт через `adb reverse tcp:53000 tcp:53000`. Сервер для стенда работает с миграциями 017–019 и импортированным каталогом.

## Android и настоящий API

Синтетический аккаунт зарегистрирован и подтверждён через Mailpit. Приложение авторизовалось на стенде. На Android просмотрены все пять анкет и создан Хмель с именем «Финик». Сервер принял публикацию, вернул тот же чекин при повторе, UI показал ровно 2 KC. [Скриншоты выбора всех пяти питомцев](evidence/android-starters.webp) · [Комната и 2 KC](evidence/android-room-2kc.webp)

После повторного запуска инструментальный тест подтвердил магазин, покупку печенья за 1 KC, угощение, открытие шкафа, получение тестовой партнёрской награды вручную, повторное погашение с тем же экземпляром и восстановление комнаты после пересоздания Activity. Адрес и UI исходного Android-клиента использованы вместе с тем же сервером PostgreSQL. [Магазин](evidence/android-shop.webp) · [Подтверждение покупки](evidence/android-checkout.webp) · [Гардероб](evidence/android-wardrobe.webp)

При остановленном backend и повторном запуске Android открыл сохранённую KraRoom и показал 1 KC с отметкой офлайн. [Снимок офлайн-комнаты](evidence/android-offline.webp)

Отдельный HTTP-прогон купил пять предметов одежды и аксессуаров и папоротник из реального импортированного каталога. Вторая сессия увидела футболку вместе с рубашкой, кепку вместе с очками, часы, декор и остаток 35 KC. Снятый декор вернулся в коллекцию. Пять надетых вещей отрисованы в нативной комнате в обеих темах. [Комплект в светлой и тёмной темах](evidence/android-outfit-themes.webp)

Первый снимок был прерван системным ANR эмулятора. В повторных прогонах ожидание переключено на видимый текст и готовность графики. Для компактных списков питомцев и действий используется обычная горизонтальная прокрутка. Из компактных списков убран PrefetchScheduler, на котором инструментальный раннер API 26 останавливался при пересоздании композиции. Повторный прогон на этом исправлении начат.

## Критерии дальнейшей приёмки

Профилирование времени загрузки, батареи и памяти на физическом слабом устройстве требует замеров. Оптическое чтение напечатанного партнёрского QR требует камеры устройства. Для тестового кода предусмотрен ручной ввод в том же сценарии. Сложные суставные движения ограничены фронтальными изображениями. Проверку совместимости всех комплектов одежды на всех питомцах нужно проводить отдельно.

Подробный статус всех требований находится в [матрице](P10_REQUIREMENTS.md). Инструкции для APK, сервера и инструментального теста находятся в [P10_RECOVERY](P10_RECOVERY.md).
