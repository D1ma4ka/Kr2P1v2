## Что установлено о Сиэтле

В исходной версии PlacesState начинался с пустой камерой. Экран открывал карту после выбора заведения, города или получения точки. Старый адаптер переносил координаты в MapLibre. Android брал последнюю позицию GPS, network или fused возрастом до 30 секунд либо первое обновление от провайдера. Для этого обновления отсутствовала проверка возраста, а оба пути принимали mock-location. Геопозиция эмулятора могла приходить как обычный GPS. Главная также автоматически использовала системную позицию при выданном разрешении.

В проверенных исходниках, настройках CI/AVD и фикстурах рабочей ветки не найдено заданного центра Сиэтла. SQL возвращает координаты заведений и центр по выбранному городу. POST nearby получает начало поиска от клиента. Изолированные тесты П7 задают точки около Москвы. Конфигурации AVD и показания устройства, на котором заметили Сиэтл, отсутствовали. Причина конкретного наблюдения остаётся неподтверждённой. Для воспроизведения на исходном устройстве сверить разрешения, включённые провайдеры, приложение фиктивных местоположений и, для AVD, Extended controls → Location. Сопоставить заданную точку с положением камеры; не помещать личные координаты в логи или Git.

## Что находится в коммите

- `android/app/build.gradle.kts` и `places/NativeVenueMap.kt` заменяют растровый адаптер на MapKit Lite 4.45.0. Оба прежних экрана используют общий адаптер. В нём управление жизненным циклом, жесты, кластеры, метки с количеством находок, выбор точки, переход по ID и возврат к списку при недоступной подложке.
- `places/DeviceLocation.kt` обслуживает оба экрана и главную. Проверки распространяются на кэш и живые обновления. Допускается приблизительная точность. Подмена на физическом устройстве отбрасывается. Для AVD запрос позиции явный и подписан как тестовый. Вручную выбранный город хранится отдельно от точки устройства. Разрешения — только на передний план.
- В `places/PlacesScreen.kt`, `PlacesViewModel.kt`, `NearbyFindsScreen.kt`, `Nearby.kt` и `VenueEvents.kt` сохранены каталог, радиусы 1/3/5/10/25/50 км, адреса, расстояния, меню и чекины. Из карточки можно открыть перечень событий и существующий экран подробностей события. Ошибка сети отделена от пустой выдачи.
- `GET /v1/venues/:id/events` читает до 30 текущих и будущих опубликованных событий конкретного доступного заведения. `GET /v1/venue-cities` сохраняет прежний ответ, а при `includeCenters=true&q=…` дополняет его центрами городов РФ из уже имеющегося GeoNames. Это позволяет выбрать город при пустом каталоге. Контракты описаны в `docs/api/openapi.yaml`. Миграций БД нет.
- Настройка ключа, выбор SDK, тарифы, условия бесплатного использования и действия владельца собраны в [инструкции MapKit](../places/YANDEX_MAPKIT.md). Для сборки без ключа предусмотрено сообщение и список из API.

## Как продолжить

1. В чистой копии выполнить `git fetch origin`, проверить локальные изменения, перейти на `p10/yandex-maps-nearby` и сверить `git status -sb`, `git log -2 --oneline`. Начать с проверки сохранённых исходников на JDK 21, Android SDK 35:

   ```sh
   cd android
   ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug :app:testDebugUnitTest
   ```

2. Для Android-приёмки запустить локальный debug backend по инструкции [П7](../places/OPERATIONS.md) с отдельной dev-БД. После миграций создать каталог `work/p7`, подготовить штатную синтетическую фикстуру `scripts/prepare_p7_fixture.mjs`, установить debug/test APK на чистый AVD API 30+ с KVM. Передать локальный файл `work/p7/android-fixture.json` через adb в `/data/local/tmp/p7-android-fixture.json`. Учётные данные в Git не переносить.
3. Без ключа на чистой установке выполнить `P7IntegrationTest#nearbyPermissionCityDisabledProviderAndNetworkRecovery`. Этот тест использует реальные HTTP, системный диалог и переключатели изолированного AVD. Проверить список, состояния при отказе, выборе города, отключении геолокации и сети. Убедиться, что после восстановления сети появляется результат. Команда:

   ```sh
   adb shell am instrument -w -e class 'ru.krapiva.app.places.P7IntegrationTest#nearbyPermissionCityDisabledProviderAndNetworkRecovery' ru.krapiva.app.debug.test/androidx.test.runner.AndroidJUnitRunner
   ```

4. На AVD выдать foreground coarse и fine, включить геолокацию, задать в Extended controls или через `adb emu geo fix` сначала долготу, затем широту. Проверить пары Москва `37.6173 55.7558`, Санкт-Петербург `30.3351 59.9343`, Суздаль `40.4495 56.4197`. Для каждой точки запустить `ru.krapiva.app.places.DeviceFixTest` тем же runner с `-e latitude … -e longitude …`. При необходимости отправить свежий fix во время запроса. На Android 12+ отдельно проверить выбор приблизительной точности в диалоге ОС.
5. После предоставления владельцем ключа локально пересобрать приложение, пройти маршрут «метка → Подробнее → Меню / События заведения», кластеризацию и повторное открытие карты. Для П7 есть `P7IntegrationTest#nativeClustersGesturesMarkersDetailAndCheckinPicker`; тест находок использует свой изолированный Smart Bar stand. Сверить атрибуцию, ошибку недействительного ключа, потерю интернета после загрузки и возврат из фона. Записать результаты по SHA, обновить прогресс. P10.4 требует отдельной команды.
