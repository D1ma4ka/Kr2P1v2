# Исходные материалы

Ожидается оригинальный `input/krapiva-0.2.0-local.apk`.
Файл приложен в чате, но инструмент `download_file` отклонил перенос с сообщением:

```text
file exceeds the executor transfer limit of 32 MiB
```

Это ограничение передачи вложения, а не ошибка APK. Содержимое файла пока
не прочитано. Точный размер и SHA-256 неизвестны.

## Варианты передачи

- Поместить исходный файл непосредственно в рабочую папку по ожидаемому пути.
- Передать бинарные части размером меньше 32 МиБ и исходный SHA-256. Части
  нужно соединить побайтно, а не распаковывать по отдельности.

Например, на Linux на компьютере владельца, в папке с оригиналом:

```sh
sha256sum krapiva-0.2.0-local.apk
split -b 24M -d -a 4 krapiva-0.2.0-local.apk krapiva.apk.part-
```

Передаются все файлы `krapiva.apk.part-0000`, `...0001` и далее.
После их получения в рабочей среде нужно проверить непрерывность нумерации,
соединить **только эти части** в порядке номеров и сравнить SHA-256 с оригиналом.
Затем поместить собранный файл по ожидаемому пути. Неполный набор частей
или несовпадающий SHA-256 нельзя использовать для аудита оригинальной сборки.

Не изменять оригинал и не включать APK в Git. Если приложению нужны split APK,
их необходимость и комплектность установить после чтения манифеста и состава
исходного файла. Не подменять отсутствующий оригинал другой сборкой.
